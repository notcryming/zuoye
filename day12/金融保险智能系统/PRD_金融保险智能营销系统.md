## 1. 项目概述

### 1.1 项目背景

某保险公司拥有 38 万+ 已购买人寿保险用户的历史数据。为提升车险交叉销售转化率、降低人工外呼成本，公司希望基于已有的用户画像数据构建机器学习预测模型，识别"高潜车险购买客户"，并结合大模型（LLM）自动生成个性化营销邮件，定向推送至高潜客户，实现"数据→预测→内容生成→触达"的智能营销闭环。

任务一已完成 XGBoost 建模与高潜客户预测（产出 `data_preprocessed.csv`、`high_value_users.csv`、模型评估报告）。任务二的目标是将该能力工程化为一个可运营的 Web 系统。

### 1.2 项目目标

| 维度 | 目标 |
| --- | --- |
| 业务目标 | 将高潜客户识别准确率（AUC）≥0.85；营销邮件点击率较人工群发提升 ≥30%；单次营销周期由 3 天压缩至 0.5 天 |
| 产品目标 | 上线一套前后端分离、支持 RBAC 权限的智能营销平台，覆盖模型管理、预测服务、邮件生成全流程 |
| 技术目标 | 系统可用性 ≥99.5%；接口 P95 响应 ≤800ms；模型文件与数据文件本地化存储，数据库承载业务元数据 |

### 1.3 项目范围

**包含（In Scope）**
- 用户与权限管理（RBAC：管理员 / 普通用户）
- 模型管理（训练、上传、下载、版本控制）
- 预测服务（数据上传、批量预测、高潜客户导出）
- 营销内容生成（Prompt 配置、LLM 调用、邮件正文生成与预览）
- 操作日志审计
- 数据存储设计（数据库 + 本地文件系统）

**不包含（Out of Scope）**
- 邮件实际 SMTP 投递通道建设（本期仅生成邮件正文并提供导出，投递对接现有邮件网关）
- 移动端 App
- 实时流式预测（本期仅批量预测）

### 1.4 名词术语

| 术语 | 说明 |
| --- | --- |
| 高潜客户 | 模型预测 `Response_pred=1`，即大概率购买车险的客户 |
| Response_prob | 模型输出的购买概率，取值 0~1 |
| RBAC | 基于角色的访问控制（Role-Based Access Control） |
| LLM | 大语言模型，用于生成个性化营销邮件 |
| Prompt 模板 | 用户可配置的大模型提示词模板，含变量占位符 |

### 2.3 权限校验原则
- 后端每个接口必须标注所需角色，由网关/中间件统一拦截校验。
- 前端按角色渲染菜单与按钮，但**后端校验为最终防线**，前端隐藏不等于无权限。
- 敏感操作（训练、模型上传/下载、用户管理）必须二次确认并写入操作日志。

## 3. 业务流程

### 3.1 整体业务流程

```
┌────────────┐   ┌──────────────┐   ┌──────────────┐   ┌──────────────┐   ┌──────────────┐
│ 1.数据准备  │ → │ 2.模型训练/   │ → │ 3.数据上传   │ → │ 4.批量预测    │ → │ 5.高潜客户    │
│  (管理员)   │   │  上线(管理员) │   │  (普通用户)  │   │  (普通用户)   │   │  导出(普通用户)│
└────────────┘   └──────────────┘   └──────────────┘   └──────────────┘   └──────┬───────┘
                                                                              ↓
                                              ┌──────────────┐   ┌──────────────────────┐
                                              │ 7.邮件推送    │ ← │ 6.Prompt配置+LLM生成 │
                                              │  (对接网关)   │   │  (普通用户)          │
                                              └──────────────┘   └──────────────────────┘
```

### 3.2 核心流程说明

**流程 A：模型训练与上线（管理员）**
1. 管理员上传训练数据（或选择历史数据集）。
2. 系统按任务一的预处理逻辑（去重、缺失值填充、编码、保费分箱、`scale_pos_weight`）自动处理。
3. 触发 XGBoost 训练，训练完成后输出评估报告（accuracy / precision / recall / AUC）。
4. 管理员确认后将该版本模型"设为线上"，模型文件落盘到本地服务器，元数据写入数据库。

**流程 B：高潜客户预测（普通用户）**
1. 普通用户上传待预测数据（Excel/CSV，字段需与训练集一致）。
2. 系统使用"线上模型"批量预测，输出 `Response_pred` 与 `Response_prob`。
3. 系统筛选 `Response_pred=1` 的记录为高潜客户，支持列表查看与导出。

**流程 C：个性化邮件生成（普通用户）**
1. 普通用户配置 Prompt 模板，可使用变量占位符（如 `{姓名}`、`{年龄}`、`{保费}`、`{购买概率}`）。
2. 选择一批高潜客户，调用 LLM 批量生成个性化邮件正文。
3. 支持邮件预览、编辑修正、批量导出（CSV/TXT），供后续邮件网关投递。

## 5. 技术架构

### 5.1 总体架构（前后端分离）

```
┌─────────────────────────────────────────────────────────────┐
│                       前端（Vue 3 + Element Plus）            │
│   登录 / 用户管理 / 模型管理 / 预测服务 / 邮件生成 / 日志      │
└───────────────────────────┬─────────────────────────────────┘
                            │ HTTP / JWT
┌───────────────────────────┴─────────────────────────────────┐
│                  后端 API 网关（FastAPI + 中间件）            │
│           统一鉴权 / RBAC 校验 / 日志拦截 / 限流              │
├───────────────┬───────────────┬───────────────┬─────────────┤
│  用户权限服务  │  模型管理服务  │  预测服务     │  营销生成    │
└───────┬───────┴───────┬───────┴───────┬───────┴──────┬──────┘
        │               │               │              │
┌───────▼───────┐ ┌─────▼─────┐ ┌───────▼──────┐ ┌────▼──────────┐
│  MySQL        │ │ 本地文件   │ │  XGBoost     │ │  LLM API      │
│  业务元数据    │ │ 模型/数据  │ │  推理引擎     │ │  (外部)       │
└───────────────┘ └───────────┘ └──────────────┘ └───────────────┘
```

### 5.2 技术栈选型

| 层级 | 技术选型 | 选型理由 |
| --- | --- | --- |
| 前端 | Vue 3 + Vite + Element Plus + Pinia + Axios | 后台管理生态成熟，组件丰富，开发效率高 |
| 后端 | FastAPI + Uvicorn + Pydantic | Python 全栈，异步高性能，自动生成 OpenAPI 文档 |
| 鉴权 | JWT（python-jose）+ Passlib(bcrypt) | 无状态、易扩展，密码加盐哈希 |
| ORM | SQLAlchemy 2.0 + Alembic | 主流稳定，支持迁移 |
| 数据库 | MySQL 8.0（或 PostgreSQL） | 关系型存储业务元数据 |
| ML | XGBoost + scikit-learn + pandas | 与任务一建模链路一致，复用预处理代码 |
| 任务队列 | Celery + Redis（训练/批量预测/批量生成异步化） | 长耗时任务不阻塞接口 |
| 文件存储 | 服务器本地磁盘（结构化目录） | 满足"模型文件与数据文件本地存储"要求 |
| LLM 对接 | HTTP Client 调用大模型 API（通义千问/文心/DeepSeek 等可切换） | 不绑定单一供应商 |

### 5.3 部署架构
- 单机部署：Nginx 反向代理前端静态资源 + 后端 API。
- 模型训练/批量预测通过 Celery Worker 异步执行，避免阻塞 Web 进程。
- 模型文件与数据文件存放于服务器 `/data/{models,datasets,exports}` 目录，路径写入数据库。

| 数据保留 | 业务数据保留 1 年；下线模型文件归档 6 个月后可清理 |

## 10. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 样本不平衡导致高潜误判 | 营销资源浪费 | 沿用 `scale_pos_weight`；提供概率阈值可调 |
| LLM 生成内容合规风险 | 品牌与合规风险 | Prompt 内置合规约束；邮件预览支持人工审核 |
| 模型文件本地存储损坏 | 预测服务中断 | 版本冗余存储；关键模型异地备份 |
| 大模型 API 不稳定 | 邮件生成失败 | 异步重试 + 供应商可切换 + 失败降级提示 |
| 数据隐私合规 | 法律风险 | 用户敏感字段脱敏存储；操作可审计 |
