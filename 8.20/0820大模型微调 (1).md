# 一、微调概念

## 1.预训练vs微调：

- 预训练：海量无监督文本，预测下一个token的方式，相应的参数。----通才

- 微调：准备专门的语料，对话形式对大模型进行继续训练，这个过程就是微调。----专才

微调的适用场景：垂直领域、特殊需求

（游戏：智能对话npc，游戏公司的ai产品经理或者大模型训练工程师，社区论坛或者语料，形成数据集用以微调npc人格大模型）



## 2. 微调SFT的主要方式：

- 全参数微调：消耗巨大；容易早成灾难性遗忘

- 冻结微调：冻结主干模型（transformer），只需要训练分层（顶层或者输出头）--基本不用

- 参数高效微调PEFT：

只训练少量新增参数adapter，基座大模型完全冻结不改权重，主流做法。

1）LoRA：在QKV矩阵旁边，增加2个低秩矩阵A,B，只更新A,B  

--Qlora：32float--->16float-->8int-->4int，混合精度 

举个例子，Qlora 4int量化做lora，单卡7b/13b的模型

2）prefix tuning

每个transformer层输入前面加一组虚拟的前缀token，只需要训练前缀的参数

3）prompting tuning

只在输入最前面加少量可学习软提示token，只训练这几个token参数

模型越大效果越好

4）p-tuning/p-tuning v2：输入/每层

5）adapter tuning

transformer每一层度加一个adapter子网络，冻结主干，只训练adapter



RLHF:同时训练奖励模型，标注成本太高（用自己的话表述出来）

---SFT-RM-PPO强化学习

--DPO：直接偏好优化，不用训练奖励模型，直接用偏好数据做损失，当前主流

--ORPO：SFT和偏好对齐合成一步。
3.对比总结表

-----

表格

| 微调方式          | 训练参数量   | 显存开销 | 推理延迟 | 主流程度   |
| ------------- | ------- | ---- | ---- | ------ |
| 全参数微调         | 100%    | 极高   | 无    | 少用     |
| 冻结微调          | 部分层     | 高    | 无    | 过时     |
| LoRA / QLoRA  | 0.1%~2% | 低    | 无    | ⭐工业首选  |
| Adapter       | 3%~8%   | 中    | 有延迟  | 部分场景   |
| Prefix Tuning | 少量      | 中高   | 有延迟  | 较少     |
| Prompt Tuning | <0.1%   | 极低   | 无    | 大模型场景  |
| DPO           | 搭配 LoRA | 低    | 无    | 偏好对齐首选 |

选型建议
----

1. 个人 / 单卡：优先 **QLoRA 做 SFT，再 DPO 偏好对齐**
2. 企业多卡资源充足：可 LoRA，复杂场景评估全量微调
3. 追求推理零额外开销：优先 LoRA，不要 Adapter/Prefix
4. 做人类偏好对齐：DPO > RLHF

# AIpaca

### SFT指令监督微调数据集

```
"alpaca_zh_demo.json"
{
  "instruction": "计算这些物品的总费用。 ",
  "input": "输入：汽车 - $3000，衣服 - $100，书 - $20。",
  "output": "汽车、衣服和书的总费用为 $3000 + $100 + $20 = $3120。"
},
```

instruction对应的内容会跟input对应的内容拼接起来作为最终的人类输入，output就是模型回答。

输入：

```
计算这些物品的总费用。
输入：汽车 - $3000，衣服 - $100，书 - $20。
```

输出：

```
汽车、衣服和书的总费用为 $3000 + $100 + $20 = $3120。
```

### **偏好数据集**

偏好数据集用于训练奖励模型，DPO和ORPO训练。对于系统指令和人类输入，偏好数据集会一个更好和更差的回答，这种训练方式，可以让模型学习什么是更好。可以是参数相对较少的模型表现优于参数更多的模型，偏好数据集需要再chosen的列中提供更好的回答，在rejected列中提供更差的回答。

```
[
  {
    "instruction": "人类指令（必填）",
    "input": "人类输入（选填）",
    "chosen": "优质回答（必填）",
    "rejected": "劣质回答（必填）"
  }
]
```

也需要在'dataset_info.json` 中的 **数据集描述** 应为：

```
"数据集名称": {
  "file_name": "data.json",
  "ranking": true,
  "columns": {
    "prompt": "instruction",
    "query": "input",
    "chosen": "chosen",
    "rejected": "rejected"
  }
}
```

### 指令监督微调数据集

相较于alpaca的数据集，sharegpt支持更多的角色种类，包括human，gpt，observation，function等，他们构成一个对象列表在Conversation列中

```
{
  "conversations": [
    {
      "from": "human",
      "value": "你好，我出生于1990年5月15日。你能告诉我我今天几岁了吗？"
    },
    {
      "from": "function_call",
      "value": "{\"name\": \"calculate_age\", \"arguments\": {\"birthdate\": \"1990-05-15\"}}"
    },
    {
      "from": "observation",
      "value": "{\"age\": 31}"
    },
    {
      "from": "gpt",
      "value": "根据我的计算，你今天31岁了。"
    }
  ],
  "tools": "[{\"name\": \"calculate_age\", \"description\": \"根据出生日期计算年龄\", \"parameters\": {\"type\": \"object\", \"properties\": {\"birthdate\": {\"type\": \"string\", \"description\": \"出生日期以YYYY-MM-DD格式表示\"}}, \"required\": [\"birthdate\"]}}]"
}
```

注意：human和observation必须出现在奇数位，gpt和function必须出现在偶数位。

```
[
  {
    "conversations": [
      {
        "from": "human",
        "value": "人类指令"
      },
      {
        "from": "function_call",
        "value": "工具参数"
      },
      {
        "from": "observation",
        "value": "工具结果"
      },
      {
        "from": "gpt",
        "value": "模型回答"
      }
    ],
    "system": "系统提示词（选填）",
    "tools": "工具描述（选填）"
  }
]
```

对于上述格式的数据， `dataset_info.json` 中的 **数据集描述** 应为：

```
"数据集名称": {
  "file_name": "data.json",
  "formatting": "sharegpt",
  "columns": {
    "messages": "conversations",
    "system": "system",
    "tools": "tools"
  }
}
```

举例子：

```
"conversations": [
  {"from": "human", "value": "北京今天天气怎么样？"},
  {"from": "function_call", "value": "{\"name\":\"get_weather\", \"arguments\":{\"city\":\"北京\"}}"},
  {"from": "observation", "value": "{\"weather\":\"晴\",\"temperature\":\"25°C\"}"},
  {"from": "gpt", "value": "北京今天天气晴朗，气温25°C。"}

```

三种角色的更替：human-function call-observation-gpt

所以，简单对话用alpaca就够了，一旦有工具调用，多步推理，就必须用sharegpt

1）点击顶部**Train**选项卡。

2）**数据集**：添加新增的my_cognition数据集，同时需要修改data/data_info.json（注意逗号）

3）数据构造的办法：可以借助ai帮你改造成alpaca格式的数据集，数据来源：[ModelScope - 数据集列表页](https://modelscope.cn/dataset

##### 第三步：设置超参数

 为了在免费GPU上快速演示，请修改以下参数：

| 参数名称      | 推荐数值       | 说明                 |
| --------- | ---------- | ------------------ |
| **学习率**   | `2e-4`     | LoRA模式下建议使用较大的学习率。 |

| **最大样本数** | `10000或-1` | -1代表全部             |
| **批处理大小** | `2`        | 每次并行处理2条数据。        |
| **LoRA秩** | `8`        | 决定适配器的参数量大小。       |

##### 第四步：**开始训练与验证**

点击**开始训练**，观察日志中`loss`值的下降。

卸载原始模型，选择“检查点”，加载新模型
