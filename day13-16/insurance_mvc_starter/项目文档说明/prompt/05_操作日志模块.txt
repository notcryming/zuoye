请基于现有的保险精准营销项目，新增 “全链路操作审计日志” 模块，要求：
【参考资料】
1. 阅读 “项目文档说明 / 03_API 接口文档.md”“日志模块/logs” 接口规范、action 枚举值、admin 专属权限约束
2. 参考 “项目文档说明 / 01_PRD_产品需求文档.md” 审计需求：训练、预测、模型导入导出、邮件生成等关键操作落日志
3. 遵循 “项目文档说明 / 04_技术框架方案.md” 分层架构、ORM 模型、路由编写规范
4. 对齐现有 models、services、api 代码风格，统一 BizException、标准分页、RBAC 权限装饰器
【要创建 / 修改的文件】
app/models/operation_log.py—— 操作审计日志 ORM 模型
字段：id、user_id、action（枚举：model_training/prediction/model_import/email_generation/email_update/email_mark/email_delete）、details（JSON 存储操作详情）、created_at
类方法：create_log (db, user_id, action, detail_dict) /paginate_logs (db, page, per_page, filter_user_id, filter_action)
app/core/dependencies.py 新增通用日志记录工具函数 record_operate_log (db, user_id, action, details)，供 model/email/data 各 service 层调用
app/api/v1/log.py—— 日志查询路由蓝图
GET /api/v1/logs（@login_required+@role_required ("admin")）日志分页查询接口，支持 user_id、action 过滤参数
app/api/v1/init.py 注册 log 蓝图
改造已有 service 层关键业务入口：
ml_service.train_model 执行完成后记录 model_training 日志
ml_service.predict_all 执行完成后记录 prediction 日志
ml_service.import_model 执行完成后记录 model_import 日志
email_service.batch_generate_emails 记录 email_generation 日志
email_service 内修改、标记、删除邮件全部对应记录 email_update/email_mark/email_delete 日志
【约束】
日志查询接口仅 admin 角色可访问，普通 user 访问返回 403+code=1003
action 字段严格限定文档定义枚举值，禁止自定义操作类型
details 字段以 JSON 存储操作上下文（训练参数、生成数量、删除 ID 列表等）便于审计追溯
所有分页返回统一 API 标准分页结构
日志写入逻辑不阻断主业务流程，写入异常仅打印日志不抛出业务异常
【验收】
admin 执行模型训练、批量生成邮件等操作后 operation_logs 表自动生成对应日志记录
admin 调用 GET /logs 可分页查询全量日志，支持用户 ID、操作类型过滤
普通用户访问 /logs 接口返回权限不足错误
日志 details 字段可存储完整操作上下文信息
